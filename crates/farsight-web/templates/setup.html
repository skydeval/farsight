{% else if step == "welcome" %}

Farsight indexes the ATProto block graph — direct blocks, moderation-list blocks, lists and list members — and answers, per account, who blocks this account, for any AppView that asks over HTTP. Every answer says how complete it is.

It stores four record types for the whole network: app.bsky.graph.block, listblock, list, and listitem (only for lists someone listblocks). It reads them live from a Jetstream firehose and, in the background, from each account's repo.

{% else if step == "backfill" %}
The sweep lists every repo that holds blocks, listblocks or lists, so that incoming answers become complete. Without it, coverage stays partial + sweep_incomplete.
Every account the sweep has not met before costs one request to the directory, so its request rate paces a first sweep; seeding from the export or a PLC mirror shortens it.
This is the hard ceiling: Farsight stores nothing new once the database is this size. The storage budget is set just under it ({{ budget_text }} now). At 90% of the budget the sweep pauses; at 100% new list admissions are deferred and writes from non-large hosts are refused (and counted). Postgres needs room on the disk beyond this figure, for its write-ahead log and for maintenance: enter what the database may use, not the size of the disk.

{% else if step == "access" && confirm_public %}
Nothing is public yet. Read what the public UI makes reachable, then confirm.

With the public UI on, anyone can open https://{{ w.hostname }}/ without logging in and see:

  • The instance hostname: {{ w.hostname }}.
  • The operator contact: {{ w.contact }}, through getStats. The public pages do not show it.
  • When the index was last updated: one line at the foot of each page.
  • Incoming blocks for any account: which accounts block it.
  • Lists naming any account: the listblocked lists it is on, each with its name, owner and number of listblocks.
  • List memberships: the members of any indexed list, and the accounts that block the list.
  • The blocks an account has made are not listed (show_outgoing_blocks is off).
  • Profile cards: for any account in a row, its handle, DID and the date the DID was created, fetched from the network when a visitor asks. The card has the account's avatar, which each visitor's browser fetches from the account's own server (show_avatars is on): that server's operator sees the visitor's address.
  • Removed records are not public.

Search engines are asked not to index the pages (crawlable is off). Accounts that are not active are not shown.

These settings, and the switch itself, can be changed later: in Settings while the admin UI is on, otherwise in config.toml.
